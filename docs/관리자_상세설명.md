# 친구야 — 관리자 페이지 와이어프레임 상세 설명

- **대상 파일**: `../관리자_와이어프레임_모바일.html`
- **플랫폼**: 모바일 (저채도 · v1)
- **성격**: 접객 중 현장에서 쓰는 운영 화면. **일반 관리자는 조회 전용**, 쓰기는 **슈퍼어드민**. 22개 관리자 기능을 17개 대표 화면으로 정리.
- **문서 목적**: 각 화면의 `id`(HTML 앵커)와 화면 코드(예: S1-A3)별 기능·규칙·화면 이동을 정의해, 다른 협업자(및 그 Claude)가 와이어프레임을 정확히 이해·수정할 수 있도록 한다.

> **주석 범례**: 🟧 규칙·로직, 🟦 확정 대기·연동, 토글=ON/OFF, 빗금=이미지, 회색 라인=텍스트 자리.

## `a-login` · S0-A2 — 관리자 로그인

- **목적**: 관리자 **아이디/비밀번호 로그인**.
- **진입**: 관리자 앱 실행 시 첫 화면.
- **주요 요소**: 아이디·비밀번호 입력, 로그인 CTA.
- **규칙·로직**: 최초 구동 시 **슈퍼어드민 생성(S0-A1)** 1회 후 잠금, 이후 이 로그인 사용.
- **화면 이동**: 로그인 성공 → 대시보드(`a-dash`).

## `a-dash` · S1-A1 — 대시보드

- **목적**: 운영 현황과 **오늘 방문 예약**을 한눈에 파악.
- **진입**: 로그인 직후, 하단 탭 '홈'.
- **주요 요소**: 지표 카드(신규 예약/입금확인 요청/취소요청/**미답변 문의**), 오늘 방문 예약 목록, 하단 탭.
- **규칙·로직**: '오늘 방문 예약' = 오늘 날짜 이용 건(일본 기준 '오늘'). **미답변 문의** 지표는 문의 관리(`a-qna`, S4-A2)로 들어가는 진입점을 겸한다.
- **화면 이동**: 예약 카드 → 예약 상세, 지표 → 해당 목록(미답변 문의 → 문의 관리 목록).

## `a-asset` · S1-A2 — 자산 관리

- **목적**: 보유 자산(자전거·낚싯대)의 **총 보유 대수** 관리.
- **진입**: 메뉴 → 자산 관리.
- **주요 요소**: 자산 카드(명칭·수량), + 등록 버튼.
- **규칙·로직**: 사유(수리/입고/외부임대)는 관리 안 함 **수량만** 관리, 삭제 = **소프트삭제**.
- **화면 이동**: + 등록 → 자산 등록 폼, 카드 → 상세/수정.

## `a-inv` · S1-A3 — 날짜별 재고 세팅

- **목적**: 날짜별 **고객 가용 수량·휴무**를 달력 뷰로 세팅.
- **진입**: 메뉴 → 재고 세팅.
- **주요 요소**: 상품 선택, 달력(여유/임박/마감/휴무 색상), 선택일 상세(총 보유·여행사 할당·고객 가용·휴무 토글).
- **규칙·로직**:
  - 셀 숫자 = 그 날짜의 **고객 가용 수량**. 색상으로 여유/임박/마감/휴무를 구분.
  - **Slice 1**은 관리자가 **고객 가용 수량 직접 세팅**.
  - **Slice 2**부터 **총 보유 − 여행사 할당 = 고객 가용**으로 자동 계산.
- **화면 이동**: 날짜 탭 → 하단 상세 편집, 저장 → 반영.

## `a-prod` · S1-A4 — 상품 관리 목록

- **목적**: 상품 목록 조회 및 **표출 ON/OFF** 관리.
- **진입**: 메뉴 → 상품 관리, 하단 탭 '상품'.
- **주요 요소**: 상품 카드(명칭·옵션·표출 토글), + 등록 버튼.
- **규칙·로직**: 상품별 **고객앱 / 여행사앱 표출**을 각각 토글.
- **화면 이동**: + 등록/카드 → 상품 등록·수정(`a-prodedit`).

## `a-prodedit` · S1-A5 — 상품 등록/수정

- **목적**: 상품의 **가격·표출·설명·이미지** 등록/수정.
- **진입**: 상품 관리 목록의 + 등록/카드.
- **주요 요소**: 고객가·여행사가, 고객앱·여행사앱 표출 토글, 타지역 반납 추가요금, 상세 설명, 이미지.
- **규칙·로직**: 여행사가 컬럼은 항상 보유(**고객앱 미노출**), 타지역 반납 추가요금은 **전기 2일 상품에만**.
- **화면 이동**: 저장 → 상품 관리 목록.

## `a-res` · S1-A6 — 예약 관리 목록

- **목적**: 전체 예약을 **상태별**로 조회·검색.
- **진입**: 메뉴 → 예약 관리, 대시보드 지표.
- **주요 요소**: 상태 탭, 검색(예약번호·여권명), 예약 카드(상태 태그).
- **규칙·로직**: 필터 **접수/완료/미입금/취소요청/취소**, 목록·검색·페이지네이션.
- **화면 이동**: 예약 카드 → 예약 상세·입금확인(`a-resdetail`).

## `a-resdetail` · S1-A7/A8 — 예약 상세 · 입금확인

- **목적**: 예약 상세 확인 및 **입금 확인 → 완료 처리**.
- **진입**: 예약 관리 목록의 예약 카드.
- **주요 요소**: 예약번호·고객·여권명·상품·이용일·입금액, 완료 처리 CTA, 미입금 강제 취소.
- **규칙·로직**: 입금 확인 시 상태 **완료**, 접수 후 **24시간 내 미입금** 시 '미입금' 표시 → 강제 취소(재고 즉시 복원).
- **화면 이동**: 완료 처리/강제 취소 → 예약 관리 목록 상태 반영.

## `a-cancel` · S1-A9 — 취소요청 처리

- **목적**: 고객 **취소요청** 검토 후 환불·취소 확정.
- **진입**: 예약 관리(취소요청 탭)의 예약 카드.
- **주요 요소**: 결제액·취소 수수료(차등)·환불 예정액·고객 환불계좌, 취소 확정 CTA.
- **규칙·로직**: 수수료는 **이용일 기준 차등**, 환불 이체는 **수동**, 이체 후 '취소' 처리 → 재고 즉시 복원.
- **화면 이동**: 취소 확정 → 예약 상태 취소.

## `a-set` · S1-A10 — 계좌 · 정책 설정

- **목적**: **입금 계좌**와 **차등 취소 수수료 정책** 설정.
- **진입**: 메뉴 → 계좌·정책.
- **주요 요소**: 입금 계좌(한국 1건), 이용일 기준 구간별 수수료율(예: D-7 이전 0%, D-3~D-6 20%, D-1~D-2 50%), 저장.
- **규칙·로직**: 구간·요율 **수치는 관리자 편집**, 여행사 취소 마감 기준일도 여기서 **유연 조정**(기본 D-3).
- **화면 이동**: 저장 → 정책 반영(취소 계산에 적용).

## `a-admins` · S0-A5/A6 — 관리자 관리

- **목적**: 관리자 계정 **등급 관리**(슈퍼어드민/일반).
- **진입**: 메뉴 → 관리자 관리(슈퍼어드민 전용).
- **주요 요소**: 관리자 카드(아이디·등급 태그), + 추가 버튼.
- **규칙·로직**: 일반 관리자는 **조회 전용**(접객용), 추가/수정/처리·설정은 **슈퍼어드민만**.
- **화면 이동**: + 추가/카드 → 관리자 등록·수정.

## `a-agency` · S2-A1/A3 — 여행사 관리

- **목적**: 여행사 계정 목록 관리 및 **사용 가능/불가** 토글.
- **진입**: 메뉴 → 여행사 관리.
- **주요 요소**: 여행사 카드(명칭·사용 토글), + 등록 버튼.
- **규칙·로직**: 토글 = 사용 가능/불가, 담당자 변경은 상세에서, **불가 시 로그인·예약 차단**.
- **화면 이동**: + 등록 → 여행사 등록(`a-agencyadd`), 카드 → 상세.

## `a-agencyadd` · S2-A2 — 여행사 등록(초대)

- **목적**: 여행사 **초대 이메일 발송**으로 계정 등록 유도.
- **진입**: 여행사 관리의 + 등록.
- **주요 요소**: 여행사명·담당자 이메일 입력, 가입 링크 발송 CTA.
- **규칙·로직**: 담당자가 링크로 **아이디·비밀번호 직접 등록**, 링크 **유효기간 1주일**, 이미 계정 있으면 발송 생략.
- **화면 이동**: 발송 → 여행사 관리 목록.
- **연동**: 여행사 측 계정 등록 화면은 여행사 파일 `g-invite`(S2-G1/G2).

## `a-alloc` · S2-A4 — 날짜별 할당 세팅

- **목적**: 여행사별·날짜별 **재고 할당 수량** 세팅.
- **진입**: 메뉴 → 할당 세팅.
- **주요 요소**: 여행사·상품·날짜 선택, 수량 스테퍼, 저장.
- **규칙·로직**: 할당 단위 = **자전거 종류·날짜별 수량**, **총 보유 − 할당 = 고객 가용**(자동), 여행사 예약기간 **+3일 ~ +3개월**.
- **화면 이동**: 저장 → 재고 세팅·여행사 예약에 반영.

## `a-invoice` · S2-A5 — 인보이스 관리 (목록)

> 비동기 데일리 로그(2026-08-24, "인보이스 기획 상세페이지 누락 수정")에 따라 기존 통합 화면을 목록(S2-A5)과 상세(S2-A6, `a-invoicedetail`)로 분리했다. 여행사 필터를 추가하고, 정산(입금) 확인은 이 화면에서 하지 않고 상세로 옮겼다.

- **목적**: 여행사별 **월별 인보이스** 자동 발행 현황을 조회.
- **진입**: 메뉴 → 인보이스.
- **주요 요소**: 이번 달 진행 중 사용액(발행예정), 여행사 필터 칩(전체 포함), 발행된 인보이스 카드(정산완료/미정산 태그).
- **규칙·로직**: 통화 **KRW**(세금 라인 없음). **매월 1일 전월 기준 자동 발행** — 관리자가 여행사·금액을 직접 입력하지 않고 그 달 여행사 예약 사용액을 합산해 마감된 달만 발행한다(수동 '등록' 버튼 없음). 이번 달(마감 전)은 **발행예정**으로 진행 중 사용액만 실시간 표시. 정산(입금 확인)은 이 화면에서 하지 않고 인보이스 상세에서만 한다.
- **화면 이동**: 카드 → 인보이스 상세(`a-invoicedetail`).

## `a-invoicedetail` · S2-A6 — 인보이스 상세 (라인아이템 · 입금 확인)

- **목적**: 인보이스 하나의 **예약 라인아이템**을 확인하고 **입금(정산) 확인** 처리.
- **진입**: 인보이스 목록의 인보이스 카드.
- **주요 요소**: 여행사·기간·정산 상태 태그, 예약 라인아이템(예약번호·상품·옵션·수량·금액, 취소 건 표시), 합계, 입금 확인 CTA(조건부).
- **규칙·로직**:
  - 라인아이템은 해당 여행사·기간의 **완료·취소 예약을 모두** 보여준다(취소 건도 무엇이 취소됐는지 확인할 수 있도록).
  - 금액은 **완료 건만** 반영하고 취소 건은 0 — 여행사 예약(고객 예약과 달리 입금 흐름이 없어 예약=즉시 완료/취소=즉시로 단순화된 모델)엔 애초에 취소 수수료 개념이 없기 때문(`apps/agency/src/data/reservationData.ts` 주석 참고). 합계 = **완료 예약 금액 합**.
  - '입금 확인' 버튼은 **미정산 상태일 때만** 노출되고, 탭 시 **'정말 입금을 확인했습니까?'**(본문: '입금을 확인하셨다면 확인 버튼을 눌러주세요.', **확인** 버튼 초록) 컨펌 후 해당 인보이스만 정산완료로 바뀐다(인보이스 단위).
- **화면 이동**: ← → 인보이스 목록, 입금 확인 → 컨펌 후 같은 화면(상태 갱신).

## `a-qna` · S4-A2 — 문의 관리 (목록)

- **목적**: 고객 1:1 문의 **목록 조회**(답변완료/대기 구분).
- **진입**: 메뉴 → 문의 관리, 대시보드 지표.
- **주요 요소**: 총건수·답변완료·대기 카운트, 문의 카드(제목·본문 일부·상태 태그).
- **규칙·로직**: 답변 유무로 **답변완료/대기**를 판정한다(예약처럼 별도 상태값을 저장하는 게 아니라 `answer` 필드 존재 여부로 계산, 실 구현과 동기화). 분류·검색 없음.
- **화면 이동**: 문의 카드 → 문의 상세·답변(`a-qnadetail`).

## `a-qnadetail` · S4-A2 — 문의 상세 · 답변

- **목적**: 문의 본문 확인 및 **답변 등록·수정**.
- **진입**: 문의 관리 목록의 문의 카드.
- **주요 요소**: 문의 제목·본문, 공개/비공개 태그, 추가 문의(있는 경우에만 표시), 답변 입력, 답변 등록/수정 CTA.
- **규칙·로직**: 비공개(PIN) 문의도 관리자 화면에는 **항상 본문을 노출**한다 — 고객앱의 PIN 잠금은 답변하는 관리자에게는 적용하지 않는다(실 구현과 동기화). 답변 등록 시 고객에게 **카카오 알림톡** 발송(알림 인터페이스, 실발송 이연). 이미 답변된 문의를 다시 열면 CTA 문구가 **답변 등록 → 답변 수정**으로 바뀐다(실 구현과 동기화).
- **화면 이동**: 답변 등록/수정 → 문의 관리 목록(상태 갱신).

## `a-cms` · S4-A1/A3 — FAQ · 콘텐츠 관리 (CMS-lite)

- **목적**: **FAQ·랜딩 히어로 배너·서비스 소개** 콘텐츠 편집.
- **진입**: 메뉴 → FAQ·콘텐츠.
- **주요 요소**: FAQ 목록(순번 표시, 항목 탭하여 수정), + FAQ 버튼, **FAQ 수정 화면 내 순서 이동(▲ 위로 / ▼ 아래로)**, **랜딩 히어로 배너 3장(탭으로 전환)** — 탭당 **제목·부제(선택 입력)·PC/모바일 이미지 각각 첨부**(카드 안 필드가 많아 라벨 구분이 잘 안 돼, 라벨 앞에 강조색 점을 붙이고 글씨를 굵고 크게 해 입력값과 구분), 서비스 소개(S4-C2) 본문 편집 영역 — **본문** 필드 라벨도 동일한 강조 스타일로 통일.
- **규칙·로직**: FAQ 등록/수정/삭제·**노출 순서** 관리, **분류·검색 없음**. 순서 변경은 목록의 화살표가 아니라 **FAQ 수정 화면 안**에서만 한다 — 목록에서 바로 화살표를 누르면 그 줄이 한 칸 밀리면서 다음 클릭이 밀려온 다른 항목의 화살표를 누르게 되는 문제가 있어, 위치가 고정된 수정 화면으로 옮겼다(실 구현과 동기화). 배너는 **3장 고정**이며 장마다 **PC용·모바일용 이미지가 각각** 필요하다(반응형으로 한 장을 늘려 쓰는 게 아니라 화면 폭에 맞는 이미지를 통째로 다르게 보여주는 방식 — 고객앱 홈 캐러셀과 동일) — 3장을 한 화면에 다 펼치면 스크롤이 너무 길어져 **탭으로 하나씩만** 편집한다(실 구현과 동기화). 이미지는 **선택 시 미리보기**까지만 되고 실제 업로드·저장 연동은 이연 상태. **저장 버튼은 배너 구역·본문 구역에 각각** 따로 둔다 — 둘은 실제로는 서로 다른 콘텐츠(다른 API 대상)라 버튼 하나로 묶으면 무엇을 저장하는지 헷갈릴 수 있어서다. 탭을 넘나들며 배너 여러 개를 고쳐도 상태는 하나로 공유돼 **배너 저장** 한 번에 3개 다 반영된다.
- **화면 이동**: FAQ 항목 → FAQ 수정, 수정 완료/취소 → FAQ · 콘텐츠 목록, 편집 → 고객 FAQ·랜딩(홈 배너)·서비스 소개(`s4-c2` 등)에 반영.
